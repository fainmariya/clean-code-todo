## 1. Error Handling — задача из одних пробелов

**Приоритет:** средний

**Место в коде:** `app.js`, функция `addTask()`.

```js
if (!taskInput.value) return;
```

**Проблема:** проверка отклоняет пустую строку, но разрешает строку, состоящую только из пробелов. Пользователь может создать задачу без видимого названия.

**Условие проявления:** ввести несколько пробелов в поле Add Item и нажать Add.

**Как проверить исправление:** убедиться, что ввод из одних пробелов не создаёт задачу, а обычный текст добавляется.

## 2. Error Handling — сохранение пустого названия

**Приоритет:** средний

**Место в коде:** `app.js`, функция `editTask()`.

```js
label.innerText = editInput.value;
```

**Проблема:** редактирование позволяет сохранить пустое название задачи. В отличие от добавления новой задачи, проверка на пустой ввод здесь отсутствует.

**Условие проявления:** нажать Edit, удалить весь текст и нажать Save.

**Как проверить исправление:** попробовать сохранить пустой текст, текст из пробелов и обычное название. Проверить, что недопустимое название не сохраняется, а допустимое сохраняется.

## 3. Naming / Maintainability — зависимость от порядка кнопок

**Приоритет:** средний

**Место в коде:** `app.js`, получение `addButton`.

```js
const addButton = document.getElementsByTagName("button")[0];
```

**Проблема:** код предполагает, что кнопка Add всегда будет первой кнопкой документа. Это делает поиск элемента зависимым от структуры HTML.

**Условие проявления:** если перед кнопкой Add появится новая кнопка, обработчик добавления задачи может быть назначен не тому элементу.

**Как проверить исправление:** после перехода к более точному селектору добавить перед Add временную кнопку и убедиться, что добавление задач по-прежнему работает.

## 4. DRY / Functions — повторение привязки обработчиков

**Приоритет:** низкий

**Место в коде:** `app.js`, два цикла в конце файла.

**Проблема:** два цикла выполняют одинаковую операцию — вызывают `bindTaskEvents()` для каждого элемента списка. Отличается только список задач.

**Условие проявления:** проблема заметна при сопровождении кода: если потребуется изменить способ инициализации задач, понадобится учитывать два участка кода.

**Как проверить исправление:** после возможного объединения логики проверить обработчики Edit, Delete и checkbox у задач в обоих исходных списках.
